# P2B1 云持久化代码验收报告

日期：2026-09-16

## 验收边界

本报告验收“云持久化代码与本地回归”，不宣称已连接用户的真实 CloudBase 数据库。真实云连接、真实微信 code、开发者工具和真机属于 P2B2。

## 已验证

- `PERSISTENCE_DRIVER=memory|mongo` 配置校验；生产环境继续拒绝内存仓储。
- Mongo 模式缺少连接串或数据库名时快速失败，错误信息不包含任何凭据。
- 玩家身份键和 unionid 使用 SHA-256；测试确认数据库调用参数不含明文 openid/unionid。
- 会话只以 token 哈希为主键，并写入 MongoDB TTL 日期字段。
- 并发首次登录场景返回唯一键下的规范 playerId。
- Mongo 连接采用 0 最小连接、5 最大连接，适合首版低配资源；启动时 ping 并幂等确保 4 个索引。
- MongoDB 官方驱动安装后 `npm audit` 为 0 个漏洞；有高危告警的 CloudBase Node SDK 已移除。
- `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` 均通过；7 个测试文件、18 个用例通过。

## 本地真实 HTTP 回归

使用真实 Fastify 监听端口和内存测试仓储（平台 gateway 为确定性验收替身）发送请求：

- `p2b1-first`：HTTP 200，`isNew=true`，返回 `playerId=acceptance-player`。
- `p2b1-repeat`：HTTP 200，`isNew=false`，复用同一 playerId。
- `p2b1-invalid`：缺少 code/anonymousCode，HTTP 400，`code=INVALID_REQUEST`。
- 验收后已通过 SIGINT 停止监听进程。

以上证明 HTTP 与登录回归未被 P2B1 破坏，不证明真实 CloudBase 已连通。

## 待 P2B2 验证

1. 使用 CloudBase 控制台提供的环境 ID、MongoDB 外部连接串执行 `npm run db:check`。
2. 在控制台确认 `players`、`sessions` 集合与 4 个索引实际创建成功。
3. 用真实 `wx.login` code 连续登录，确认相同微信账号稳定返回同一 playerId，且数据库无明文 openid/token。
4. 微信开发者工具与真机验证 HTTPS 合法域名、超时、游客降级和 token 持久化。
5. 抖音环境取得凭据后重复平台隔离与真机验收。

## 结论

P2B1 本地代码验收通过，可以独立提交；P2 整体仍未完成。缺少真实 CloudBase 环境配置时，不得标记 P2B2 或 P2 完成。
