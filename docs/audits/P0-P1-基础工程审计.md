# P0/P1 基础工程审计

日期：2026-09-16

## 审计范围

- 后端仓库状态、分支和远端。
- 前端登录、启动、云存档及平台适配契约。
- Node.js 本地运行环境。
- 微信、抖音部署所需的配置边界。

## 审计结论

1. 后端仓库是空仓库，当前分支为 `main`，尚无首个 commit；远端为 GitHub `origin`。
2. 前端已统一取得小游戏临时 code，并预留后端登录、token、playerId 和服务端存档恢复位置。
3. 前端当前 HTTP、用户服务和云存档控制器是禁用 stub，P2/P3 必须与后端接口同步恢复。
4. 本机 Node.js 和 npm 可用于 TypeScript 后端开发。
5. P0/P1 不需要真实 AppSecret；密钥仅通过云端 Secret/环境变量提供。
6. 微信与抖音使用相同业务核心、不同身份 adapter 和部署环境，数据按 `(platform, appId, openId)` 隔离。

## 本阶段变更范围

- 建立 Node.js + TypeScript + Fastify 基础工程。
- 建立严格配置校验、统一响应、requestId、日志脱敏和健康检查。
- 建立玩家实体、仓储接口、平台认证接口和内存实现。
- 建立自动化测试、接口文档和环境变量模板。

## 风险与处理

- 平台云数据库类型尚未最终确认：本阶段只定义 repository，不绑定数据库 SDK。
- 暂无真实 AppId/Secret：生产模式缺少两项配置时快速失败。
- 空仓库首次提交会同时包含两份开发计划；提交前必须检查暂存清单。
- 前端仓库可能有用户未提交改动：P0/P1 不修改前端。

## 后台影响

有。新增的统一响应、requestId、平台枚举、玩家实体和仓储边界，是管理后台后续契约基础；管理后台计划无需改变页面范围。
