# P2 双平台登录审计

日期：2026-09-16

## 审计范围

- 后端平台认证、玩家、会话与 API 契约。
- 游戏前端 `PlatformHelper`、`PlatformSDK`、`LoadingActivity`、`zysdk/http.ts`、`zysdk/user.ts`。
- 微信 `wx.login -> code2Session` 与抖音 `tt.login -> code2Session` 差异。

## 发现

1. 游戏可统一取得平台临时凭证，但 `LoadingActivity` 的旧平台枚举没有处理 `BYTEDANCE`，会落入 Web。
2. 抖音匿名登录会返回 `anonymousCode`，旧启动链只保存 `code`。
3. `zysdk/http.ts` 和 `zysdk/user.ts` 仍是禁用 stub。
4. 旧登录日志会序列化完整响应，可能输出自有 token。
5. 后端已有平台认证 gateway 接口和内存玩家仓储，但缺少真实微信/抖音 adapter、会话和登录路由。
6. 后端尚未选定平台云数据库；内存仓储只能用于开发和联调，不能作为生产持久化方案。

## 执行范围

- 实现微信和抖音 code2Session adapter、错误归一化。
- 实现玩家 upsert、自有 opaque token、token 哈希会话仓储。
- 实现 `POST /v1/auth/platform-login` 和 schema 校验。
- 恢复前端受限 HTTP 客户端与登录 API；所有 SDK 请求只能访问 `Env.baseUrl`。
- 修复抖音平台枚举和 anonymousCode 传递，保留游客降级。
- 删除完整登录响应日志。

## 暂不包含

- 真实云数据库持久化（P3 前置工作）。
- 云存档读写（P3）。
- 管理后台页面。
- 使用真实 AppId/AppSecret 的平台真 code 验收；需要云环境 Secret 和合法域名后执行。

## 回滚

- 后端可回滚 P2 commit，P1 `/health` 不受影响。
- 前端可回滚对应 P2 commit，恢复游客模式 stub。
- 登录失败、后端不可用或超时仍使用本地玩家数据启动。

## 后台影响

有。管理后台后续以 `playerId` 查询玩家；平台 openid 不通过玩家 API 返回。新增错误码应进入错误日志中文解释。
