# P2C2 002 版本与数据库探测审计

日期：2026-09-16

## 审计范围

- CloudBase Run `miao-travel-wechat-002` 的发布状态、流量和非敏感运行配置。
- 微信 AppSecret 与 CloudBase 服务端 API Key 轮换后的服务连通性。
- CloudBase 文档数据库探测脚本对已有集合、缺失探针文档场景的处理。
- 本次变更是否影响玩家 API、数据库字段和管理后台计划。

## 审计证据

- 脱敏后的 CloudBase CLI 服务详情显示服务状态为 `normal`，在线版本为 `miao-travel-wechat-002`，承载 100% 流量。
- 默认 HTTPS 域名 `GET /health` 返回 HTTP 200，响应确认生产环境使用 `wechat` 与 `cloudbase-http`。
- 登录接口使用无效测试 code 返回 HTTP 401 和 `PLATFORM_AUTH_REJECTED`，证明请求已到达微信 code2Session；测试未产生玩家或会话数据。
- 轮换后的本地服务端 API Key 能访问 `players`、`sessions`，但首次探测被 `DOCUMENT_NOT_FOUND` 中止。

## 发现

`ensureCollection` 通过读取固定探针文档判断集合是否存在。集合已经存在但探针文档不存在时，CloudBase 返回 `DOCUMENT_NOT_FOUND`；旧实现只识别“集合不存在”，因而把正常状态当成失败。

该问题仅影响验收脚本，不影响线上玩家与会话 repository。未知错误和权限错误仍必须抛出，不能通过宽泛 catch 掩盖。

## 执行方案

1. 独立识别缺少文档与缺少集合两类错误。
2. 缺少探针文档时认定集合存在并继续；仅在明确缺少集合时创建集合。
3. 为缺少文档、缺少集合、未知错误补充单元测试。
4. 重新执行 lint、类型检查、单元测试、构建以及真实数据库写入、读取和清理。

## 后台计划影响

本次没有新增或修改 API、数据库字段、错误码、RBAC 权限点和后台页面需求。管理后台仍需保留 CloudBase requestId 关联和敏感环境变量禁止展示的约束。
