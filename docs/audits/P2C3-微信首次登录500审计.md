# P2C3 微信首次登录 500 审计

日期：2026-09-16

## 现象

- 微信小游戏已通过 `wx.cloud.callContainer` 命中 `miao-travel-wechat`。
- `POST /v1/auth/platform-login` 返回 `INTERNAL_ERROR`（HTTP 500），证明环境关联、服务名和容器入口均已生效，失败发生在服务内部。
- CloudBase CLI 当前只能拉到该版本的构建/部署过程事件，未返回应用 stdout；诊断不能把“没有运行日志输出”误判为没有服务异常。

## 根因

CloudBase 文档数据库按主键读取不存在的文档时，会抛出 `DOCUMENT_NOT_FOUND`，而不是稳定返回 `data: []`。玩家仓储原实现没有识别该语义，因此新微信账号首次登录查询不到玩家时抛出异常，并被统一错误处理器转换为 500。

同样的问题也存在于会话按 token 哈希查询路径，虽未触发本次登录故障，但会导致合法的无效/过期 token 被误报为 500。

## 修复边界

- 仅把明确的“文档不存在”转换为仓储的 `undefined`。
- 权限、网络、配额及其他未知错误继续向上抛出，禁止静默降级为空数据。
- 错误识别逻辑下沉到生产代码中的 CloudBase 公共错误模块；真实数据库探针复用同一语义，避免测试脚本和生产实现漂移。
- 不改变登录 API、响应字段、数据库字段、错误码或敏感信息策略。

## 后续云端门禁

本地验收通过后发布新版本，再使用微信开发者工具获取新的临时 code 验证：首次登录成功且 `isNew=true`，第二次登录 playerId 不变且 `isNew=false`。平台 code 一次性使用，不能复用旧请求进行复测。
