# P4A 云存档故障策略审计

日期：2026-09-16

## 审计范围

- 前端冷启动读档、本地优先启动、定时/退后台上传、幂等重试与 revision 冲突处理。
- 后端幂等重放、CAS 冲突、数据库异常、错误脱敏与 requestId 追踪。
- P4 要求的断网、超时、429/配额、500、重复请求、退后台、进程被杀和多设备冲突。

## 发现

1. 前端已在网络失败后保留同一份幂等请求，并使用 5 秒至 5 分钟的指数退避。
2. 前端已在退后台时先强制写本地档，再尝试云上传；即使进程被杀，下次启动仍有本地恢复点。
3. 409 已停止自动覆盖并保留本地档，后端只返回云端 revision/hash/时间摘要。
4. 存在两个风险：冷启动 GET 失败后会永久关闭本次运行的云同步；除 409 外所有错误均重试，会对 400/401/413 等永久拒绝产生无意义请求。

## 修正策略

- 冷启动 GET 失败：继续使用本地档，保留本地已知 revision；后续本地数据变脏后仍允许上传，并依靠 CAS 阻止覆盖更新的云档。
- 自动重试仅适用于网络错误/HTTP 0、408、425、429 和 5xx。
- 409 标记冲突并停止自动覆盖；其他明确 4xx 及未知编程异常停止本次运行的自动同步，但不清理本地档。
- 数据库/配额异常对外仅返回 `INTERNAL_ERROR` 与 requestId，服务端未知 500 日志仅记录错误类型和框架 requestId，不记录 SDK 错误正文、存档、token 或内部配置。

## 验收边界

- 本阶段先用自动测试覆盖故障分类、幂等、冲突、脱敏与本地保护。
- 微信开发者工具需补验断网后恢复、退后台上传和强杀后恢复。
- 双设备冲突及抖音开发者工具/真机仍需真实平台证据，自动测试不代替平台验收。

## 管理后台影响

- 不新增玩家数据字段或管理 API。
- 错误日志页仍需按 HTTP 状态、业务码和 requestId 查询；客户端的重试/停止分类不应展示 token 或存档正文。
