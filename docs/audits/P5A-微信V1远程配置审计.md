# P5A 微信 V1 远程配置审计

## 审计范围

- 本阶段只服务微信 V1；抖音部署、兑换码和完整管理后台不在范围内。
- 后端当前只有健康检查、平台登录和云存档接口，没有启动配置路由。
- 前端 `ChannelConfigLoader` 只负责构建渠道与服务地址；账号登录后会直接启用微信云存档，没有运行时总开关。
- 游戏必须继续满足“后端不可用仍能使用本地档进入游戏”，因此远程配置不能成为强启动依赖。

## 契约决定

- 新增匿名只读 `GET /v1/bootstrap-config`，返回维护信息、最低客户端版本和 `cloudSaveEnabled`。
- 每个部署环境只保存 `remote_configs/bootstrap` 一条文档，避免扫描、分页和额外集合关联。
- 服务端文档缺失时使用安全默认值：不维护、无最低版本限制、允许云存档。
- 响应提供稳定 `ETag` 和 5 分钟缓存；客户端 TTL 被限制在 1～15 分钟。
- CloudBase 公网网关实测会覆盖应用的缓存头和 ETag；应用层 304 仅作为可迁移契约保留，当前微信端以本地 TTL 缓存为准。
- 客户端网络失败时优先使用旧缓存，没有缓存才使用内置默认值；任何失败都不阻断本地游戏。
- 维护状态会停用本次运行的云存档并显示一次提示，但不会禁止进入本地游戏。

## 发布与安全

- 不开放公网写配置接口；首版通过需要 CloudBase 服务端 API Key 的本地 CLI 发布。
- CLI 必须显式设置 `BOOTSTRAP_CONFIG_CONFIRM=PUBLISH`，并在文档中保存 revision、更新时间和操作者。
- 匿名接口不返回 `updatedBy/updatedAt`，日志和响应均不包含 API Key。
- 后续管理后台复用同一文档和字段，但改由受保护的管理 API 写入并追加管理审计日志。

## 风险与回滚

- 错误关闭云存档：玩家继续使用本地档；重新发布 `cloudSaveEnabled=true` 即可恢复。
- 错误维护提示：重新发布关闭维护；客户端最长使用缓存 5 分钟。
- 配置文档损坏：接口返回脱敏 500，客户端自动使用旧缓存或默认配置。
- 代码回滚：旧客户端不会请求新接口；新增集合不影响登录和云存档旧路由。

## 验收用例

1. 无配置文档返回默认开启状态。
2. 发布关闭配置后接口返回新 revision、`cloudSaveEnabled=false` 和新 ETag。
3. 携带匹配 `If-None-Match` 返回 304。
4. 客户端命中有效缓存时不重复拉取；请求失败时继续本地启动。
5. 维护或总开关关闭时不读取、不写入云存档，并显示一次提示。
6. 恢复开关后重新冷启动，正常读取已有云档且 revision 不丢失。

## 部署访问策略补充

- `wx.cloud.callContainer` 要求云托管服务启用 `MINIAPP` 访问策略；公网运维请求需要 `PUBLIC`。
- 部署必须同时使用 `PUBLIC,MINIAPP`。仅配置 `PUBLIC` 会导致小游戏返回 `SERVICE_FORBIDDEN`，即使公网 URL 仍为 200。
