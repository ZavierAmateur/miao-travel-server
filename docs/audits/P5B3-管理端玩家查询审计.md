# P5B3 管理端玩家查询审计

## 契约与数据边界

- 管理 API 复用独立管理员 Cookie 会话，只授予具有 `player:read` 权限的 `admin/operator`。
- 列表支持玩家 ID 精确匹配、平台、状态和不透明游标；不提供昵称模糊枚举。
- 列表不读取头像；详情按玩家 ID 单条读取资料。
- 平台 openid、unionid、存档正文、幂等键和哈希均不返回后台。
- 云存档仅返回 revision、客户端版本、客户端/服务端保存时间和大小摘要。

## 持久化审计

- 内存仓储用于本地开发和自动测试。
- CloudBase 精确 ID 使用 `players.id` 条件查询；列表使用过滤条件、`createdAt desc`、offset cursor 和 limit。
- 生产启用前需确认 `players` 集合具备 `id` 唯一查询索引，以及平台/状态与 `createdAt` 的组合索引；本阶段未在生产库执行索引变更。

## 风险结论

- offset cursor 在并发新增玩家时可能产生跨页漂移，V1 后台查询可接受；若后续要求强一致导出，应改为 `(createdAt,id)` 键集游标。
- 当前详情读取昵称与头像会暴露个人资料给有 `player:read` 权限的运营角色，访问通过管理会话约束；独立“资料查看”审计动作留待管理审计阶段完善。
