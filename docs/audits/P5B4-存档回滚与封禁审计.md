# P5B4 存档回滚与封禁审计

## 存档回滚

- 回滚来源只允许同一 `cloud_saves` 文档的 `previous`，不创建历史集合。
- 请求必须携带当前 `expectedRevision`；CloudBase 以 `_id + revision` 条件更新，防止并发覆盖。
- 回滚结果把旧快照写成正文并生成 `current.revision + 1`，回滚前正文轮换为新的 `previous`。
- 仅 `admin` 角色具有 `save:rollback`；原因长度为 2～200，成功后写审计日志。

## 封禁

- `operator` 可临时封禁与解封；永久封禁只允许 `admin`。
- 临时封禁必须提供晚于当前时间的毫秒时间戳；到期后玩家鉴权自动恢复为 active。
- 玩家平台登录会返回真实 `isBanned/banReason/banExpire`；已有会话在云存档或资料接口鉴权时检查玩家状态并返回 `PLAYER_BANNED`。
- 封禁、解封记录操作者、目标玩家、requestId、IP、原因以及类型/到期时间；内部备注限制 500 字符。

## 边界与风险

- V1 没有通用金币、体力编辑接口；后台只能查看白名单 `user` 字段差异并回滚完整快照。
- 本地内存仓储与 CloudBase 条件更新代码已自动验证；本阶段不对线上玩家执行真实封禁或回滚。
- CloudBase 真实 CAS 回滚需在隔离测试玩家上部署验收，禁止用生产真实玩家做破坏性演练。
