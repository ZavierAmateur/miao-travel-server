2026-09-20

## 审计范围

- CloudBase Run 服务 `miao-travel-wechat` 的管理接口部署配置。
- 管理员认证、玩家查询、存档诊断/回滚、封禁/解封和审计日志。
- 生产环境写操作的隔离范围与清理策略。

## 部署前审计结论

1. 后端 `main` 与 `origin/main` 一致，管理接口代码已提交，工作区无既有业务改动。
2. `admin_users`、`admin_sessions`、`admin_audit_logs` 等 8 个集合通过 CloudBase HTTP 真实读写探测。
3. 管理接口通过环境变量启用；密码、AppSecret 和 CloudBase API Key 不进入仓库与验收报告。
4. V1 后台按内部简易工具收缩：只启用单个初始化管理员，不开发管理员列表、账号增删改、多角色配置页面和会话管理页面。
5. 回档、封禁和解封禁止作用于真实玩家；云端验收必须创建带唯一标记的隔离玩家，并在验收后核对清理结果。

## 部署中发现的问题

### 010 版本仍返回管理员登录 500

- 服务、路由和管理员集合均正常，直接领域服务登录可以复现数据库错误。
- CloudBase 查询结果会携带只读 `_id`；管理员登录更新 `lastLoginAt` 时，旧仓储把 `_id` 一并写回。
- CloudBase 拒绝更新并返回 `INVALID_PARAM: 不能更新_id的值`。

### 修复决策

- 管理员和管理会话从 CloudBase 读取后显式重建领域模型。
- 不向领域层传播 `_id` 等数据库元字段。
- 增加管理员更新与会话撤销两项仓储回归测试。
- 修复提交：`e682c53 修复CloudBase管理员登录元字段写回错误`。

## 安全边界

- 验收输出不包含管理员密码、Cookie、玩家 token、openid、AppSecret 或 CloudBase API Key。
- 只读验收可查询现有玩家数量和结构，但不在报告记录玩家 ID、昵称或头像地址。
- 写操作仅使用临时隔离玩家；验收后按唯一测试昵称只读复查，剩余数量为 0。
- V1 保留管理员用户、会话和高风险操作审计三个集合，它们属于安全底座，不扩展为复杂管理员管理功能。
