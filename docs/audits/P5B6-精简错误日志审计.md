# P5B6 精简错误日志审计

## 审计时间

2026-09-20

## 需求边界

- V1 只提供错误列表、单条详情、时间范围、业务错误码和 requestId 查询。
- 不开发指标仪表盘、告警通知、工单流转、负责人分派、错误正文全文检索或堆栈查看。
- 管理接口仍使用 HttpOnly Cookie 和 `error:read` 权限，浏览器不直连 CloudBase。

## 存储决策

- 新增 `admin_error_logs` 集合，仅在请求失败时追加一条脱敏记录。
- API 字段固定为 `id/occurredAt/requestId/method/path/statusCode/code/message/errorName`。CloudBase 文档使用 `errorCode/safeMessage` 存储后两项，避免 `code/message` 与 SDK 协议字段冲突。
- `path` 保存路由模板，不保存玩家 ID 和查询参数；不保存请求体、Cookie、Token、昵称头像、平台身份、存档正文、幂等键和错误堆栈。
- 管理员登录页正常探测 `/admin/v1/auth/me` 产生的 `ADMIN_AUTH_REQUIRED` 不入库；错误日志接口自身失败也不递归写入同一集合。

## 资源与查询边界

- 列表按时间倒序，默认 20 条、最大 50 条。
- 为避免免费数据库被无界扫描，单次筛选最多检查最近 1000 条，使用不透明游标继续查询。
- CloudBase 写入失败不覆盖原业务错误响应，只在 stdout 记录脱敏后的写入失败类型。
