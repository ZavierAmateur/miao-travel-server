# P8A 闯关榜后端与管理接口审计

日期：2026-09-22

## 产品范围

- 微信小游戏展示同玩好友闯关榜，由微信开放数据域读取，最多展示前 100 名并固定展示当前用户真实名次。
- 管理后台展示全平台闯关榜，固定每页 20 条。
- 管理后台保留挑战榜页签，但 V1 不开发挑战榜数据和接口。

## 现状

- 云存档 `save.modules.user.level` 是玩家当前到达的关卡，初始值为 1，通关后加 1。
- 微信昵称头像保存在独立 `player_profiles` 集合，不属于云存档。
- 原后端没有排行榜集合和排行榜查询接口。
- 直接分页读取完整 `cloud_saves` 后再逐条查询资料，会放大后台每次翻页的数据库读取量。

## 决策

- 新增轻量 `level_leaderboard` 投影，每名玩家一条记录，以 `playerId` 为文档 ID。
- 只在云存档关卡变化、资料变化或管理员回滚存档时同步，不在每次后台查询时解析完整存档。
- 管理接口复用 `player:read` 权限，不增加新的管理员角色或权限配置。
- 后台接口只返回全平台数据，不接收、保存或推断微信好友关系。
- 使用单字段 `sortKey` 完成“关卡降序、达到时间升序、用户 ID 升序”的稳定排序，减少 CloudBase 组合索引配置。

## 数据安全

- `user.level` 必须是 1～1,000,000 的安全整数。
- 排行榜不保存平台 OpenID、UnionID、会话 Token 或完整云存档。
- 历史回填脚本只读玩家、资料与云存档，并写入轻量排行榜投影，不修改原存档。
