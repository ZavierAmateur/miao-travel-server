# P8B 闯关榜筛选审计

日期：2026-09-22

## 需求

- 管理后台闯关榜增加微信昵称、平台、用户 ID 三个筛选条件。
- 筛选必须由后端完成，不能只过滤当前页 20 条数据。
- 筛选后仍固定每页 20 条，排名保留未筛选全榜中的真实名次。

## 字段语义

- 微信昵称：去除首尾空格后执行包含匹配，最长 50 个字符。
- 平台：精确匹配 `wechat` 或 `bytedance`。
- 用户 ID：去除首尾空格后精确匹配，最长 128 个字符。
- 三个条件可以组合，条件之间使用“并且”关系。

## 实现决策

- 继续复用 `GET /admin/v1/leaderboards/level`，不增加重复接口。
- CloudBase 按原榜单 `sortKey` 顺序分批读取，每批最多 100 条，在服务端匹配条件并按命中结果分页。
- 扫描过程中记录原榜单位置，因此筛选结果不会把排名重新编号。
- V1 管理查询频率低且当前数据量小，采用分批扫描可避免额外配置复合索引；后续数据量明显增长时再增加专用搜索索引。

## 安全与边界

- 查询仍要求管理员 Cookie 和 `player:read` 权限。
- 请求 Schema 限制平台枚举及字符串长度。
- 不返回平台 OpenID、会话凭据或完整云存档。
