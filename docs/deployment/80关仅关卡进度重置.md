# 80关仅关卡进度重置

策略：`generation=mixed99-20261105` 不变，`progressVersion=rhythm80-20261106`。正常 PUT 必须包含 `save.modules.user.levelProgressVersion` 同值，否则返回 `SAVE_PROGRESS_VERSION_MISMATCH`。同 generation 旧进度 GET 保留真实 revision、完整资产供迁移；旧 generation 继续按原策略处理。

仅将 user 的 level=6、levelMaxProgress=0、winnerStreakCount=0、levelProgressVersion 更新为目标版本。current/previous 分别判断：同版本已玩新进度不重置，旧 previous 单独修复。后台 rollback 额外即时修复历史 previous 的四字段，覆盖服务部署与批量迁移间隙。客户端、服务端都须先启用此版本。

## 操作次序

1. 保留现有云环境配置文件，不将 .env、API Key 或其他密钥复制到交付材料。
2. 先 dry-run，使用全新绝对路径备份目录。此时无需新版 health，可对现有同目标 health 核对目标指纹；dry-run 不写云库。
3. 部署已完成全部测试的新服务。核对健康接口 data.saveGeneration、data.progressVersion、data.saveTarget，以及 persistence=cloudbase-http、platform=wechat。
4. 复核 dry-run before.jsonl 里的 current/previous 和 fingerprints，generation 不匹配记录单独核对。apply 使用另一个新目录保存执行时刻的备份。
5. 核对 report.json：updated=verified；conflicts=0、leaderboardConflicts=0、concurrentAdvanced=0。冲突或复读时已有新版并发写入会退出码2，不自动覆盖；用新目录重跑并核对。中途出错保留已写备份，已完成用户版本幂等，重跑不会清掉新进度。
6. 查看云档/排行抽样，保留 before.jsonl、manifest.json、report.json。微信好友平台分数由新版客户端登录后重发。

```sh
# cwd: /Volumes/work/Projects/Server/miao-travel-server
# 示例目录需替换为真实且每次唯一的绝对路径。
npm run save:reset-progress:wechat -- --backup-dir=/absolute/secure/rhythm80-dry-run
npm run save:reset-progress:wechat -- --backup-dir=/absolute/secure/rhythm80-apply --health-url=https://YOUR_HOST/health --apply
```

工具保存 before.jsonl（整条原始记录，包含 previous；每条 fsync 完成才写数据库）、manifest.json（无密钥的版本/目标指纹）、report.json（汇总）。新文件0600，目录0700；禁止覆盖已有 before.jsonl。dry-run 也写本地备份但不写云库。健康目标不匹配直接停止；apply 还强制匹配 generation 与 progressVersion。

存档按 _id 稳定分页，仅以原 revision CAS 局部更新快照/摘要/版本元数据，递增 revision 并使旧幂等请求失效，不删除任何文档。hash/sizeBytes 对 current 与 previous 各自重算。四个字段以外完整 payload 的 SHA-256 fingerprint 前后必须相等；每次成功 CAS 后复读真实落库快照核对摘要、资产和 previous。如果复读已出现更高 revision，则报告 concurrentAdvanced，不假称当时快照已验证。previous generation 不一致会停止，保留原档供人工核对。

排行仅局部更新 level、reachedAt、scoreUpdatedAt、sortKey 和版本标记，CAS 条件绑定旧 level/scoreUpdatedAt；昵称、头像、其他资料字段保持原样。读取最新新版云档避免重跑拉低已玩新进度。云档 CAS 冲突者跳过排行迁移。

正常客户端保存先经白名单过滤，再在仓储原 revision CAS 内合并已有模块与省略 user 字段。未知客户端字段不能新增或覆盖已有未知资产；adFreeCount、totalRechargeAmount 省略时保留。客户端显式管理的字段正常覆盖。合并后的内容重算 hash/sizeBytes，超过512KiB安全拒绝；幂等身份仍使用规范客户端请求的 requestHash，重试不会多加 revision。

CLI 等待数据库请求、报告文件写入、stdout 输出回调以及 finally 中的备份文件关闭全部完成后，显式以既有 exitCode 退出，避免 CloudBase SDK 后台定时器/连接导致成功执行后挂起。
